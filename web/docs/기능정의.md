# 기능 정의

운영 문서와 설정을 근거로 답하는 RAG의 웹 화면이다. 검색·답변 백엔드는 rag-ops 엔진(engine/, Python·FastAPI)가 맡는다.

## 원칙

- 답변에는 항상 **근거 위치**와 **검증 상태**를 붙인다.
- 근거가 부족하면 답하지 않고 **보류**한다.
- 운영·개발·샘플 **환경을 섞지 않는다**.

## 구성

```
브라우저(rag-ops web 화면) → API 서버(rag-ops 엔진, FastAPI) → PostgreSQL+pgvector
                                                   → TEI(임베딩·리랭커)
                                                   → LLM 서버(별도로 띄움)
```

## 사용자와 권한

| 역할 | 할 수 있는 일 |
| --- | --- |
| 관리자 | 사용자 관리, 설정 변경, 모든 기능 |
| 편집자 | 문서 등록·수정·삭제, 평가 실행 |
| 사용자 | 질문하기, 자기 대화 보기 |

## 기능 (1차 구현 범위)

| 번호 | 화면 | 기능 | 권한 |
| --- | --- | --- | --- |
| F1 | 로그인 | 아이디·비밀번호로 로그인, 로그아웃 | 전체 |
| F2 | Playground | 질문 입력 → 답변 + 근거(파일·위치) + 검증 상태 표시. 근거 부족 시 "보류" | 사용자 |
| F3 | Playground | 질문할 때 환경(운영/개발/샘플) 선택 | 사용자 |
| F4 | Conversations | 내 질문·답변 목록과 다시 보기 | 사용자 |
| F5 | Knowledge base | 문서 업로드 + 메타데이터 입력(환경, 대상, 출처, 성격, 검증 상태, 확인일) | 편집자 |
| F6 | Knowledge base | 문서 목록·검색·삭제, 적재 상태(대기/완료/실패) 보기 | 편집자 |
| F7 | Evaluations | 평가 질문셋 실행 → 지표(검색 성공률, 근거 일치, 보류 정확도) 보기 | 편집자 |
| F8 | Run history | 질문마다 검색된 조각, 점수, 걸린 시간 보기 | 편집자 |
| F9 | Settings | 사용자 추가·역할 변경 | 관리자 |

## 나중에 할 것

- RAG pipeline 화면에서 단계 설정 바꾸기 (지금은 보기만)
- Home 대시보드 실제 수치
- 답변에 대한 사용자 피드백(좋아요/틀림)
- SSO 로그인

## 하지 않는 것

- 외부 LLM API 사용 (LLM은 직접 띄운 서버만 쓴다)
- 회원가입 (관리자가 계정을 만든다)

## 사용자가 정할 것

- 청킹 방식
- 보류 기준 (어떤 점수·조건이면 답하지 않을지)
- LLM 모델과 띄울 위치
- 비밀번호 저장·세션 방식

## 완료 기준

- F1~F9가 실제 백엔드와 연결되어 동작한다 (샘플 데이터·데모 표시 제거).
- 다른 계정의 대화는 보이지 않는다.
- 같은 평가 질문셋으로 결과를 다시 낼 수 있다.
